## 1. 阻断性问题：花色增强 obs/action 不一致

### 问题描述

`augment.py` 中 `augment_action` 使用 push 语义（`perm[old_suit]`），而 `augment_obs` 使用 pull 语义（`perm[new_suit] = old_suit`）。两者不一致导致 50% 训练 episode 中观测和动作空间的花色映射错乱。

### 详细分析

以 `perm = (2, 0, 1)` 为例：

**`augment_obs`（pull 语义）：**
- 万位置 ← 条数据（`perm[0]=2`）
- 筒位置 ← 万数据（`perm[1]=0`）
- 条位置 ← 筒数据（`perm[2]=1`）

**`augment_action`（push 语义）：**
- 万动作 → 条动作（`perm[0]=2`）
- 筒动作 → 万动作（`perm[1]=0`）
- 条动作 → 筒动作（`perm[2]=1`）

**`_apply_augment_mask`：** `new_mask[augment_action(i, perm)] = mask[i]`
- `mask[0]`（万1合法性）→ `new_mask[18]`（条1位置）
- `mask[9]`（筒1合法性）→ `new_mask[0]`（万1位置）
- `mask[18]`（条1合法性）→ `new_mask[9]`（筒1位置）

**增强后的不一致：**

| 位置 | 观测数据 | 动作合法性 | 正确应为 |
|------|----------|------------|----------|
| 万位 | 条的牌   | 筒的合法性 | 条的合法性 |
| 筒位 | 万的牌   | 条的合法性 | 万的合法性 |
| 条位 | 筒的牌   | 万的合法性 | 筒的合法性 |

### 影响

- 50% 训练 episode 中模型接收到矛盾的监督信号
- 模型无法学到正确的花色感知策略
- 直接导致定缺功能异常（全部选条）
- 所有历史训练 checkpoint 均受污染

### 根因

`augment_action` 第 56/62 行的注释 `Fix: use perm[old_suit] not perm.index(old_suit)` 实际上是引入 bug 的那次改动。原始的 `perm.index(old_suit)` 与 `augment_obs` 的 pull 语义一致。

### 修复方案

1. `augment_action` 改回 `perm.index(old_suit)`
2. `_inverse_action` 中逆置换计算相应调整（使用 `perm[old_suit]` 作为逆映射）
3. 修复后从头重新训练

## 3. 神经网络层面评估（设计优秀）

### 架构（约 20M 参数）

```
SuitAwareResNetEncoder:
  输入 (473×27) → SuitAwareConv1d(473→256) → SuitPositionalEncoding
  → 4 segments × [5×BottleneckBlock + TileAttention]
  → SpatialPoolingProj(256×27 → 1024)
  → LSTM(2层, 512)
  → 解耦 Actor/Critic 头(1024→512→34/1)
  → 辅助头(对手向听+听牌预测)
```

### 设计亮点

- SuitAwareConv1d 强制花色隔离，TileAttention 作为唯一跨花色交互机制——正确的归纳偏置
- SpatialPoolingProj 用 4 个可学习 query token 做注意力池化，保留牌位结构信息
- 解耦 Actor-Critic 避免策略和价值函数的梯度冲突
- 辅助头放在 LSTM 之后，激励 LSTM 在隐状态中维护对手信息
- Oracle 编码器（525 通道）用于 KL 蒸馏，提供完美信息教师信号

### 观测空间（473×27 学生 / 525×27 Oracle）

| Section | 通道数 | 内容 |
|---------|--------|------|
| 1: 手牌 | 5 | 4ch one-hot + 最后摸牌 |
| 2: 游戏上下文 | 13 | 分数、排名、庄家、进度 |
| 3: 定缺 | 17 | 自家+3对手定缺+完成状态 |
| 4: 游戏状态 | 5 | 牌墙、听牌宽度、岭上 |
| 5-6: 牌河 | 232 | 自家+3对手各58ch |
| 7: 可见牌 | 48 | 副露概览、暗杠、打牌数 |
| 8: 防守 | 9 | 对手花色弃牌比例 |
| 9: 派生 | 11 | 剩余牌、门前、副露数 |
| 10: 手牌分析 | 6 | 听牌、向听 one-hot |
| 11: 动作上下文 | 12 | 最后弃牌、候选、碰杠和 |
| 12: SP Table | 99 | 每张牌的 EV/胜率/听牌概率曲线 |
| 13: 番种配置 | 7 | 可用番种开关 |
| 14: 对手手牌信息 | 6 | 手牌数+副露来源 |
| 15: 現物 | 3 | 对手弃过的安全牌 |
| Oracle 额外 | 52 | 对手真实手牌、SP摘要、危险度 |

| 阶段 | 步数 | 对手 | 关键特性 |

- 由于增强 bug，所有历史训练结果均受污染，需修复后重训

### 中等问题

| 问题 | 描述 |

## 5. 评估/搜索层面评估（设计精良）

### ISMCE（信息集蒙特卡洛评估）

三层架构：
1. 基础：无约束世界采样
2. 约束：尊重对手定缺约束
3. 知情：OpponentHandPredictor 概率加权采样（Gumbel-max trick）

配置：64 worlds × 8-depth rollouts，防守感知（非线性 danger² 缩放）

### RTPA（实时策略调整）

6 信号听牌估计：副露比例、摸切率、幺九比例、花色集中度、弃牌进度、后期加成。
自适应温度：听牌时降温（0.8）攻击，对手听牌时升温（1.5）防守。

### Arena + Elo

- 1v3 评估，随机座位消除庄家偏差
- 同分平均排名
- Bootstrap 95% 置信区间
- 训练中后台周期性评估

### 联赛系统

- 最多 200 个历史 checkpoint 池
- 多项式衰减 + 均匀地板采样
- 可选 Elo 加权采样（高斯中心）
- 20% 自对弈概率
- 稀疏淘汰保持时间覆盖
