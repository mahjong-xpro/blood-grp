**真正的Bug在定缺阶段的观测编码中。**

## 确凿证据

### 位置: `blood-v2/crates/engine/src/obs/student.rs:94-100`

```rust
// Section 3: 定缺信息 (通道 18-20)
if board.phase == Phase::DingQue {

## 为什么导致100%索子偏差

### 神经网络视角

1. **定缺阶段，Section 3（通道18-20）完全为零**
2. **模型没有任何关于手牌花色分布的信息**
3. **没有这个关键信息，模型无法做出明智的决策**
4. **模型退回到以下因素产生的偏差:**
   - 初始权重初始化
   - 训练数据分布
   - 数据增强伪影
   - 随机探索模式

### 为什么特别是索子(100%)?

索子(动作33)的偏差可能来自:

1. **动作空间顺序**: 动作 31=万, 32=筒, 33=索
2. **权重初始化**: 最后线性层对动作33的权重可能初始值略高
3. **训练动态**: 一旦出现小偏差，就会自我强化:
   - 模型更频繁选择索子
   - 获得更多索子的训练样本
   - 学会更多选择索子
   - **正反馈循环**

4. **数据增强交互**: 花色增强(50%样本)可能产生微妙偏差:
   - 当排列映射 索→万 时，模型看到动作31
   - 当排列映射 索→筒 时，模型看到动作32
   - 但`augment.py:43`中的**反向映射是错的**(用了`perm.index()`而不是`perm[]`)
   - 这在83.3%的增强样本中产生了系统性错误
   - 这些错误可能放大了索子偏差

### 修复#2: 观测编码 ✅ (真正的修复)

- **这是关键修复**

- 将探索从0.01增加到0.03
- 帮助跳出局部最优
- 但不能修复信息缺失

### 修复#4: 奖励塑形 ❌ (从未生效)

#[pymethods]
impl BloodMahjongEnv {
    pub fn get_agent_hand(&self) -> Vec<u8> {
        self.board.players[0].hand.tiles.clone()
    }
}
```

## 结论

定缺bug是由定缺阶段**缺失观测数据**引起的。模型字面上没有关于花色分布的信息，所以退回到有偏的默认值(索子100%)。

修复很简单但需要**重新编译Rust引擎**来激活观测编码更改。奖励塑形是锦上添花但不是关键 - 仅观测修复就应该解决问题。
