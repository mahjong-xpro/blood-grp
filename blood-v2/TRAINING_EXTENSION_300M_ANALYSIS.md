# 训练量扩展至300M步分析

> 问题：将Elite阶段训练量从200M扩展到300M步的影响和配置调整

---

## 一、收益分析

### 1.1 预期Elo提升

**基于训练量-Elo关系的估算**：

| 训练量 | 预期Elo | 相对提升 | 说明 |
|--------|---------|---------|------|
| 200M步 | 1500-1650 | 基准 | 当前计划 |
| 300M步 | 1550-1730 | +50~80 | 扩展50% |
| 500M步 | 1650-1800 | +150~200 | Suphx水平 |

**收益递减规律**：
- 前100M步：快速提升（+300~400 Elo）
- 100M-200M步：中速提升（+150~200 Elo）
- 200M-300M步：慢速提升（+50~80 Elo）
- 300M-500M步：缓慢提升（+50~100 Elo）

**原因**：
1. 早期学习基础策略，提升快
2. 中期精调策略，提升中等
3. 后期微调细节，提升缓慢但稳定

### 1.2 超人类水平概率提升

**200M步**：
- 强人类水平（Elo 1500+）：85-90%
- 超人类水平（Elo 1650+）：55-60%

**300M步**：
- 强人类水平（Elo 1500+）：**95%+**
- 超人类水平（Elo 1650+）：**70-75%**
- 顶级超人类（Elo 1700+）：**40-45%**

**关键提升**：超人类水平概率从55-60%提升到70-75%（+15%）

### 2.3 Arena评估频率调整

**当前配置**：
```yaml
blood_arena_eval_every: 2000000     # 每2M步评估一次
# 200M步总共评估：100次
```

**建议调整**：
```yaml
blood_arena_eval_every: 3000000     # 每3M步评估一次
# 300M步总共评估：100次（保持相同评估次数）
```

**原因**：
- 保持评估总次数不变（100次）
- 减少评估开销（每次100局 × 60步 ≈ 10分钟）
- 后期Elo变化缓慢，3M步间隔足够

### 2.4 联赛快照频率调整

**当前配置**：
```yaml
league_add_every: 100000            # 每100K步添加快照
league_max_pool_size: 200           # 池容量200
# 200M步总共快照：2000个 → 保留最近200个
```

**建议调整**：
```yaml
league_add_every: 150000            # 每150K步添加快照
league_max_pool_size: 200           # 池容量保持200
# 300M步总共快照：2000个 → 保留最近200个
```

**原因**：
- 保持池覆盖的训练历史长度（200×150K = 30M步）
- 减少I/O开销
- 后期策略变化缓慢，150K步间隔足够

## 三、资源需求

### 3.1 训练时间

**当前配置**（200M步）：
- 并行模式：200-300 steps/sec
- 预计时间：200M / 250 / 3600 / 24 ≈ **9-13天**

**扩展配置**（300M步）：
- 并行模式：200-300 steps/sec
- 预计时间：300M / 250 / 3600 / 24 ≈ **14-20天**

**增加时间**：+5-7天

### 3.2 存储需求

**Checkpoint存储**：
```
每个checkpoint：~500MB（模型+优化器+统计）
保存频率：每300秒（5分钟）
300M步 @ 250 steps/sec = 1,200,000秒 = 333小时
Checkpoint数量：333小时 × 12/小时 = 4000个
总存储：4000 × 500MB = 2TB
```

**实际存储**（保留策略）：
- 最新10个：5GB
- 每1M步保留1个：300个 × 500MB = 150GB
- 联赛池：200个 × 500MB = 100GB
- **总计**：~250-300GB

### 3.3 GPU需求

**单卡RTX 4090**（24GB）：
- ✅ 可行
- Batch size: 2048（安全）
- 混合精度：FP16
- 预计时间：14-20天

**双卡RTX 4090**（并行）：
- ✅ 可行（需要分布式训练支持）
- 预计时间：7-10天
- 需要修改配置启用多GPU

## 六、风险评估

### 6.1 潜在风险

1. **过拟合风险**：低
   - 联赛池200个checkpoint提供足够多样性
   - 数据增强（花色置换）持续生效
   - 自博弈持续产生新数据

2. **Entropy崩溃风险**：中
   - 当前0.47，持续下降
   - 300M步可能降至0.35-0.40
   - 缓解：entropy_floor=0.009，必要时提高到0.012

3. **训练停滞风险**：低
   - 向听奖励衰减到30%后保持
   - Oracle权重已降至0.01（最小）
   - 联赛系统持续提供挑战

### 6.2 缓解措施

**Entropy监控**：
```python
# 在callbacks.py中添加自动调整
if env_steps > 200_000_000:
    if entropy < 0.40 and elo_stagnant:
        # 临时提高entropy系数
        cfg.exploration_loss_coeff *= 1.2
```

**早停检查**：
```python
# 每10M步检查
if env_steps % 10_000_000 == 0:
    if elo_improvement_last_10M < 10:
        log.warning("Elo improvement < 10 in last 10M steps, consider early stop")
```
