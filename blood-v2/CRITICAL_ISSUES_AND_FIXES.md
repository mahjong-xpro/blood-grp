## 🚑 紧急修复方案

### 方案A: 激进修复 (推荐)

**目标**: 打破学习停滞，恢复学习信号

#### 1. 提高学习率下限
```yaml
lr_adaptive_min: 1e-4  # 从5e-5提升到1e-4 (2倍)
```

**理由**: 
- 当前锁定在5e-5导致学习过慢
- 提升到1e-4可以加速学习
- 仍然安全（competitive阶段用的就是1e-4）

#### 2. 放宽KL阈值
```yaml
lr_schedule_kl_threshold: 0.002  # 从0.0005提升到0.002 (4倍)
```

**理由**:
- 当前KL均值0.001-0.002
- 阈值0.0005过于严格
- 放宽到0.002匹配实际KL

#### 3. 移除优势裁剪
```yaml
adv_clip: 0.0  # 从2.0改为0.0 (禁用)
```

**理由**:
- 优势标准差已经极低(0.30)
- 裁剪进一步削弱信号
- 禁用裁剪恢复完整信号

#### 4. 增加PPO clip
```yaml
ppo_clip_ratio: 0.2  # 从0.15提升到0.2
```

**理由**:
- 当前裁剪比例仅2.2%
- 提升clip允许更大更新

#### 5. 增强奖励塑形
```yaml
reward_tsumo_bonus: 0.2        # 从0.1提升到0.2
reward_deal_in_penalty: 0.1    # 从0.05提升到0.1
reward_shanten_progress: 0.01  # 从0.003提升到0.01
reward_rank_bonus: 0.3         # 从0.15提升到0.3
```

**理由**:
- 增加奖励方差
- 提升学习信号强度

#### 6. 降低value_loss权重
```yaml
value_loss_coeff: 0.5  # 从1.0降到0.5
```

**理由**:
- Critic学习失败
- 降低权重减少错误影响

### 方案B: 保守修复

**目标**: 渐进式改善

#### 1. 适度提高学习率下限
```yaml
lr_adaptive_min: 7.5e-5  # 从5e-5提升到7.5e-5 (1.5倍)
```

#### 2. 适度放宽KL阈值
```yaml

```

#### 3. 减小优势裁剪
```yaml

```
