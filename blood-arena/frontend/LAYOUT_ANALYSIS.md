# 左右两家手牌区域深度分析

## 1. 当前结构（左右 DOM 完全一致）

- `player-info-and-hand` 内顺序：**信息卡 (上) → 手牌行 (下)**，即 `flex-direction: column` 时先渲染信息卡、再渲染手牌。
- 牌样式、尺寸、间距左右共用，无差异。

## 2. 旋转后为何“看起来不一样”

整体旋转后，**同一套结构**在左右两侧会变成**镜像**：

| 旋转 | 列「上」(信息卡) → 视口 | 列「下」(手牌) → 视口 |
|------|-------------------------|------------------------|
| 右家 `-90deg` | 视口**右**（靠边） | 视口**左**（靠中心） |
| 左家 `90deg`  | 视口**左**（靠边） | 视口**右**（靠中心） |

所以：
- **右家**：信息卡在牌列的**右侧**（靠屏幕右缘），手牌在左侧（靠中心）。
- **左家**：信息卡在牌列的**左侧**（靠屏幕左缘），手牌在右侧（靠中心）。

也就是说：**信息卡相对手牌的位置是反的**——一边在左、一边在右。

此外，整块旋转导致**文字方向**也相反：
- 右家整块 -90deg → 姓名/分数竖排、呈顺时针方向（从上往下读）。
- 左家整块 90deg → 姓名/分数竖排、呈逆时针方向（从下往上读）。

所以「不一样」来自两点：
1. **信息卡在牌列的不同侧**（左 vs 右）。
2. **姓名/分数阅读方向相反**（一个顺一个逆）。

## 3. 修改思路：让左右“逻辑一致”

目标：两边都是「信息卡在中心侧、手牌在边缘侧」，且文字阅读方向一致。

- 在 **player-info-and-hand** 上对左右两家使用 **flex-direction: column-reverse**，把视觉顺序改成「手牌 (上) → 信息卡 (下)」。旋转后：
  - 右家：手牌到视口右（边缘），信息卡到视口左（中心）→ 信息卡在牌列**左侧**（靠中心）。
  - 左家：手牌到视口左（边缘），信息卡到视口右（中心）→ 信息卡在牌列**右侧**（靠中心）。
- 这样两边都是「信息卡在中心侧、手牌在边缘侧」，**相对关系一致**。
- 再对 **player-info-card** 做**反旋转**，抵消整块旋转，使姓名/分数在左右两侧阅读方向一致（例如都恢复为水平或同向竖排）。
