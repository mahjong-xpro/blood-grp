# 人机对战界面深度分析与完全重构说明

## 一、现状分析

### 1.1 信息架构
- **顶部栏**：状态文案 + 开始/再来一局按钮 + 四人分数与定缺，挤在一行，小屏易挤。
- **牌桌**：四家（上/左/右/下）+ 中央标题，结构清晰但视觉层次弱。
- **通知**：全屏居中大字，仅和牌/结束时出现，无持久结果展示。
- **操作区**：绝对定位在牌桌下方，与手牌重叠风险，定缺/碰杠过/自摸混用同一样式。
- **Debug**：固定左下角，生产环境也应可关闭或隐藏。

### 1.2 视觉与层次
- 牌桌绿色与背景对比不足，缺少「桌沿」或边框，牌桌边界不清晰。
- 当前回合仅靠顶部栏「轮到你出牌」和分数项高亮，手牌区无明确「可操作」反馈。
- 结束态只有短暂 notification，无最终分数汇总与明确「再来一局」入口。

### 1.3 交互与可用性
- 手牌可点击时无 hover/焦点样式区分，易误点或不知可点。
- 断线/未连接时仅状态栏文字变化，缺少醒目提示。
- 无键盘/无障碍支持（aria、焦点管理、减少动画选项）。

### 1.4 结构与可维护性
- CSS 按「区域」组织，但类名不统一（混用 zone-*、hand、meld-group），扩展新状态需加选择器。
- 无设计 token 体系（间距、圆角、字号阶梯），改版需到处改数值。
- 单文件 Vue，逻辑与视图耦合，但体量尚可；可抽 computed 便于模板表达「阶段」「是否显示操作区」等。

### 1.5 响应式
- 固定 grid 列宽/行高（px），小屏或大屏均可能溢出或留白，未做 min/max 或 clamp。

---

## 二、重构目标

1. **语义化**：用 `<header>` / `<main>` / 区域 landmark，便于阅读与无障碍。
2. **设计系统**：CSS 变量统一 token（颜色、间距、圆角、阴影、字号），BEM 风格类名。
3. **状态驱动**：用「阶段」与「是否轮到我」驱动样式（如手牌高亮、操作区显隐），结束态专用结果面板。
4. **层次清晰**：牌桌与背景分离、中央标题突出、当前回合与操作区更醒目。
5. **可访问与健壮**：关键按钮与状态带 aria，连接/错误态明显；可选减少动画。

---

## 三、重构实施摘要

- **HTML**：语义结构、游戏结束结果面板（分数列表 + 再来一局）、Debug 可关闭、必要 aria。
- **CSS**：Design tokens → 基础 → 布局 → 组件（header/score/table/tile/meld/river/action/overlay/result）→ 状态（turn/ended）。
- **JS**：增加 computed（如 `gamePhase`、`isMyTurn`、`showResultPanel`），模板用其控制显隐与 class，逻辑不变。
