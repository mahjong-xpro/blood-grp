# 定缺辅助与系统奖励 — 对照分析

## 一、系统主奖励（mortal）

### 1.1 定义与计算

- **来源**：`RewardCalculator.calc_delta_points(player_id, scores_history, final_scores)`  
  - `scores_history`：每局**开始时**四人分数，形状 `[num_kyoku, 4]`  
  - `final_scores`：对局**结束时**四人分数  
  - 构造该玩家的分数序列：`seq = [scores_history[:, player_id], final_scores[player_id]]`  
  - **局间差分**：`delta_points = seq[1:] - seq[:-1]`，长度 = num_kyoku  
  - 即：`kyoku_rewards[k]` = 玩家在第 k 局的**得分变化**（局初→下一局初，最后一局为局初→终局）

- **训练侧缩放**：`kyoku_rewards = delta_points / 10000.0`  
  - 约定：**1.0 reward ≈ 10000 点**，便于与 Q 量级匹配

### 1.2 在训练中的用法

- 每个 step `i` 对应一局：`at_kyoku[i]` = 局索引  
- 该 step 的「回报」：`gamma ** steps_to_done[i] * kyoku_rewards[at_kyoku[i]]`  
  - **同一局内所有 step 共用同一个 kyoku_rewards[k]**，即共用该局的得分变化  
  - `steps_to_done` 表示到「下一 done」的步数，用于折扣

- **Q 目标（无定缺辅助时）**：  
  `q_target_mc = gamma ** steps_to_done * kyoku_rewards`  
  - 即：用「折扣后的本局得分变化」作为该 step 的 MC 目标，政策学习的是**最大化期望局得分**（在给定数据分布下）

### 1.3 性质小结

| 性质 | 说明 |
|------|------|
| **零和** | 每局四人得分变化之和为 0，对局结果由 final_scores 决定 |
| **信用分配** | 同一局内所有 step 共享同一局 delta，不区分局内哪一步「贡献」了得分 |
| **量级** | kyoku_rewards 约在 [-1, 1] 量级（±10000 点 → ±1.0） |

## 二、定缺辅助与主奖励的叠加方式

### 2.1 方案 A：奖励塑形

- **Q 目标**：`q_target_mc = gamma ** steps_to_done * kyoku_rewards + ding_que_bonus`  
  - 非定缺步：`ding_que_bonus[i] = 0` → 与原来完全一致  
  - 定缺步：`ding_que_bonus[i] = ding_que_quality[k] * ding_que_aux_scale`（如 0.02），与主奖励**相加**

- **量级对比**：  
  - 主奖励：约 ±1.0（一万点 ±1）  
  - 定缺 bonus：约 ±0.02（quality ∈ [-1,1]，scale=0.02）  
  - **主奖励主导**，定缺项为小幅修正

- **语义**：在定缺步，Q 被拉向「折扣局得分 + 一点启发式好坏」，相当于给定缺步多一个**即时、小幅度**的正/负信号，不改变非定缺步的目标，也不改变零和（bonus 只加在该玩家该步的 Q 目标上）。

### 2.2 方案 B：CE 监督

- **不修改奖励、不修改 Q 目标**  
- 仅在定缺步对动作 31/32/33 加交叉熵损失，权重 `ding_que_ce_weight`（如 0.1）  
- 作用：在梯度层面把策略往「启发式最佳花色」拉，与主奖励**并行**，不改变主回报定义

---

## 三、与主奖励系统的关系总结

| 维度 | 主奖励系统 | 定缺 A（塑形） | 定缺 B（CE） |
|------|------------|----------------|--------------|
| **是否改主奖励** | — | 不改主奖励定义，只在该步 Q 目标上**加一项** | 不改 |
| **作用步** | 所有 step | 仅定缺步 | 仅定缺步 |
| **零和** | 保持 | 保持（bonus 只算在该玩家该步） | 保持 |
| **量级** | 约 ±1.0 | 约 ±0.02 | 不占 reward 量级 |
| **信用分配** | 局内共享 delta | 定缺步多一个即时项 | 仅梯度 |

结论：

1. **主奖励仍是唯一「对局结果」信号**：局得分变化、零和、终局排名都由主奖励体现。  
2. **定缺辅助是在定缺步上的「小叠加」**：A 在 Q 目标上加一个小常数项，B 在梯度上加一项，都不替代主奖励。  
3. **与主奖励兼容**：不破坏零和、不改变非定缺步目标；若启发式与真实最优定缺一致，辅助会加速学习；若偶发不一致，因权重小，主奖励仍可纠正。

---

## 四、设计上的注意点

1. **scale 不宜过大**：`ding_que_aux_scale` 保持 0.01～0.05，避免定缺项在数值上盖过局得分（约 ±1.0）。  
2. **消融**：可用 `ding_que_aux_enabled=false`、`ding_que_ce_weight=0` 做消融，对比「仅主奖励」与「主奖励 + 定缺辅助」的胜率/得分，验证辅助是否带来收益。  
3. **监控**：`ding_que/match_rate` 与主 reward / 胜率一起看，便于判断定缺是否在学、辅助是否有效。

---

## 五、一句话对照

- **主奖励**：每局得分变化（/10000），零和，同一局内 step 共享局 delta。  
- **定缺 A**：仅在定缺步的 Q 目标上加上 ±0.02 量级的启发式项，主奖励仍主导。  
- **定缺 B**：仅在定缺步加 CE 梯度，不改 Q 目标与奖励。  
- **整体**：主奖励系统不变；定缺辅助是在定缺步上的小叠加与梯度修正，与系统奖励兼容，可按当前配置使用并配合消融与监控。
