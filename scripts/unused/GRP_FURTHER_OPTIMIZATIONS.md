#### 1.2 添加剩余牌数信息（低优先级）

**当前问题**：
- 无法知道"距离流局还有多远"
- 流局时的查花猪、查大叫会导致大幅分数变化

**优化方案**：
```rust
// 扩展 GRP_SIZE 从 9 到 10
[kyoku, score[0], score[1], score[2], score[3],
 agari[0], agari[1], agari[2], agari[3],
 tiles_left/56.0]  // 归一化的剩余牌数
```

**优点**：
- 能预测流局情况
- 能考虑"时间压力"对排名的影响

**缺点**：
- 局数信息已经部分表达了时间信息
- 改进效果可能不明显

**实现难度**：🟢 低

**评估**：优先级较低，可以先观察当前实现效果。

---

#### 1.3 添加分数差距特征（中优先级）

**当前问题**：
- 只记录绝对分数，没有相对差距信息
- 分数差距可能比绝对分数更能预测排名

**优化方案**：
```rust
// 扩展 GRP_SIZE 从 9 到 12
[kyoku, score[0], score[1], score[2], score[3],
 agari[0], agari[1], agari[2], agari[3],
 score_gap_01, score_gap_02, score_gap_03]  // 玩家0与其他玩家的分数差距
```

**优点**：
- 相对差距可能比绝对分数更有预测性
- 能更好地表达"竞争态势"

**缺点**：
- 可能冗余（GRU可能已经能学习到差距）
- 增加特征维度

**实现难度**：🟡 中等

**评估**：可以尝试，但需要实验验证效果。

### 2. 模型架构优化

#### 2.1 调整超参数（中优先级）

**当前配置**：
```python
hidden_size = 64
num_layers = 2
```

**优化方向**：

1. **增加 hidden_size**
   - 当前：64
   - 建议：128 或 256
   - **优点**：更强的表达能力
   - **缺点**：训练时间增加，可能过拟合

2. **增加 num_layers**
   - 当前：2
   - 建议：3 或 4
   - **优点**：更深的网络，更强的学习能力
   - **缺点**：训练时间增加，梯度消失风险

3. **调整学习率**
   - 当前：1e-5
   - 建议：尝试 5e-6 到 2e-5
   - **优点**：可能提高收敛速度或最终性能

**实现难度**：🟢 低（只需修改配置文件）

**评估**：建议先进行超参数搜索，找到最优配置。

---

#### 2.2 尝试 Transformer 架构（高优先级，实验性）

**当前架构**：GRU (RNN)

**优化方案**：使用 Transformer 替代 GRU

**优点**：
- 更好的长序列建模能力
- 并行计算，训练更快
- 注意力机制能更好地捕捉关键信息

**缺点**：
- 需要重新实现模型
- 可能需要更多数据
- 计算资源需求更高

**实现难度**：🔴 高

**评估**：可以作为长期实验方向，但需要充分验证。

---

#### 2.3 添加注意力机制（中优先级）

**优化方案**：在 GRU 后添加注意力层

```python
class GRP(nn.Module):
    def __init__(self, hidden_size=64, num_layers=2):
        # ... existing code ...
        self.attention = nn.MultiheadAttention(hidden_size, num_heads=4)
    
    def forward_packed(self, packed_inputs):
        output, state = self.rnn(packed_inputs)
        # Add attention
        attended, _ = self.attention(output, output, output)
        # ... rest of the code ...
```

**优点**：
- 能更好地关注关键局数
- 可能提高预测准确性

**缺点**：
- 增加模型复杂度
- 需要更多训练数据

**实现难度**：🟡 中等

**评估**：值得尝试，但需要实验验证。

### 3. 训练策略优化

#### 3.1 数据增强（中优先级）

**当前问题**：
- 训练数据可能不足
- 数据分布可能不均匀

**优化方案**：

1. **数据增强**：
   - 对局数据镜像（交换玩家位置）
   - 分数归一化增强
   - 时间序列增强

2. **数据平衡**：
   - 平衡不同结束方式（3人胡牌 vs 流局）
   - 平衡不同排名分布

**实现难度**：🟡 中等

**评估**：如果数据不足，数据增强可能很有帮助。

---

#### 3.2 损失函数优化（低优先级）

**当前损失**：CrossEntropyLoss

**优化方案**：

1. **加权损失**：
   - 对不同排名给予不同权重
   - 更关注"排名预测错误"的惩罚

2. **Focal Loss**：
   - 关注难预测的样本
   - 可能提高模型性能

**实现难度**：🟡 中等

**评估**：优先级较低，当前损失函数可能已经足够。

---

#### 3.3 多任务学习（低优先级）

**优化方案**：
- 同时预测排名和最终分数
- 可能提高模型泛化能力

**实现难度**：🟡 中等

**评估**：实验性方向，需要充分验证。

---

### 4. 特征提取时机优化

#### 4.1 添加局中特征（低优先级）

**当前问题**：
- 只在 `StartKyoku` 时提取特征
- 可能丢失局中的关键信息

**优化方案**：
- 在每局结束时也提取特征
- 或在一局中的关键事件时提取

**实现难度**：🟡 中等

**评估**：优先级较低，当前实现可能已经足够。

---

### 5. 工程优化

#### 5.1 特征提取性能优化（低优先级）

**实现难度**：🟢 低

**评估**：如果数据加载成为瓶颈，值得优化。
